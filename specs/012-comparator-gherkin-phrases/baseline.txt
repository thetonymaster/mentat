## 3a. SC-009's "byte-identical" needs one caveat (found 2026-09-11)

SC-009 says an engine with zero contributed phrases must produce **byte-identical** output to
`0f9dcea` across every existing golden. Taken literally that is unachievable, and not for any
behavioural reason.

godog's pretty formatter annotates each step with the **source location** of the step definition
it bound:

    Given the agent target "bot"        # metadata.go:75 -> *world

`testdata/golden-hermetic.txt` captured that verbatim, so adding a comment anywhere above the
`reg.Step` loop in `metadata.go` churns the golden — `metadata.go:75` became `metadata.go:107`
with the rendered output otherwise identical.

**Resolution**: `normalizeGoldenStdout` now rewrites the line number to `<LINE>`, keeping the
filename. Registration moving to a different file still churns the golden (a real change to the
single registration path); the line within that file does not.

SC-009 should be read as **byte-identical after the golden's own normalization** — which is
already how it treats the trailing duration line (`<DURATION>`). This is a clarification of an
existing convention rather than a new exemption.

### A SECOND caveat: the golden clause holds, the behavioural clause no longer does

Found at convergence (Phase 10 / T089, 2026-09-11). SC-009 carries two claims, and after
Phase 9 they have different answers.

**The golden clause still holds — measured.** With zero contributed phrases, `make ci` and an
uncached `go test -tags e2e` are both green and no golden churns.

**"Proving the feature costs nothing when unused" is no longer true of BEHAVIOUR.** Phase 9
closed the built-in half of the step-argument gap, and that check runs for EVERY engine,
including one that contributes nothing:

    a suite that PASSED at 0f9dcea with a surplus docstring on a built-in step now FAILS.

That is not a regression and it is not an accident. The scenario that used to pass was
reporting a verdict that never read the expectation its author wrote — godog discarded the
argument in silence. Failing it is the entire point. But it means the honest reading of SC-009
is now:

> An engine with zero contributed phrases produces byte-identical output *after normalization*
> for every suite that was **already correct**. Suites relying on an argument being silently
> discarded change verdict, deliberately.

Recorded rather than reverted: this was a deliberate, maintainer-approved scope change, made
after convergence surfaced that the defect reached all 40 built-in steps and not just
contributed phrases. The alternative — scoping the fix to phrases to protect the letter of
SC-009 — would have left the larger half of the defect in place to satisfy a success criterion,
which is the tail wagging the dog. The CHANGELOG marks it **BREAKING (authoring)** for the same
reason.

### Why `cmd/mentat` fell — measured, not asserted

| | statements | covered | % |
|---|---|---|---|
| `cmd/mentat` @ `main` | 281 | 195 | 69.4% |
| `cmd/mentat` final | 187 | 116 | 62.0% |
| `internal/steps` @ `main` | 442 | 393 | 88.9% |
| `internal/steps` final | 753 | 672 | 89.2% |
| **combined @ `main`** | 723 | 588 | **81.3%** |
| **combined final** | 940 | 788 | **83.8%** |

The feature-walking logic (`checkFeature`, `featureFiles`, `lineMap`, `newIDGen`,
`dedupeSort`) MOVED from `cmd/mentat` into `internal/steps` so the CLI and the library
validate entry point share one implementation. That removed 94 statements from
`cmd/mentat`, **79 of them covered** — an 84%-covered block, well above the package's
69.4% average. Removing an above-average block lowers the average; no coverage was lost,
and the combined figure rose by 2.5 points.

What remains uncovered in `cmd/mentat` is `main`, `usage` and `runMain` — 0% at baseline
too, being the `os.Exit` shell the pure seams exist to keep untested.

**Why `make ci` is green regardless**: the coverage gate
(`.claude/skills/coverage/coverage.sh:44-47`) SKIPS `*/cmd/*`, `*/cmd`, `*/mocks` and
`*/mocks/*`. `cmd/mentat` has therefore never been subject to the 80% floor and its
number is informational. Stated because the argument above would otherwise look like
what keeps CI green, and it is not.

**Conclusion**: `cmd/mentat`'s regression is arithmetic and explained; every other
touched package is above the floor, and `internal/steps` — where nearly all the new code
lives — finished above its baseline.

### The e2e golden caught what `make ci` structurally cannot

The SC-005 stdout golden (`cmd/mentat/testdata/golden-green.txt`) captured the same
step-definition source annotation §3a describes — `# metadata.go:75 -> *world` — and 012's
documentation of `registerSteps` moved that line to 107. The e2e lane FAILED on it.

`make ci` does not compile `//go:build e2e`, so nothing caught this until the e2e run. That is
exactly why the spec refused to let a green `make ci` discharge SC-012, and it is the second time
in this feature that running both surfaces was the only thing that worked.

**Fix**: `normalizeStdout` in `e2e/golden_test.go` now applies the same line-number normalization
as `normalizeGoldenStdout` in the root package, and the committed golden was regenerated
(7 insertions, 7 deletions — every one of them a `metadata.go:NNN` → `metadata.go:<LINE>` token,
no rendered content changed). The two goldens capture the same annotation and now treat it the
same way; a comment on either side would otherwise churn one and not the other.

**Standing lesson**: a green `make ci` is not evidence about the e2e goldens. Run
`go test -tags e2e` after any change to step registration, and after any change to the
FILE LAYOUT around it — not only to the step table.
